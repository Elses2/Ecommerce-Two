## 1. Carpeta `docs/` — documentación de código fuente

### Qué pasó

Se generó y versionó documentación HTML de tipo API reference a partir de los
comentarios JSDoc del proyecto usando **TypeDoc**. La carpeta `docs/` contiene
253 archivos estáticos (HTML, CSS, JS, SVG, PNG) que conforman un sitio
documental navegable.

### Estructura de `docs/`

```
docs/
├── .nojekyll              ← deshabilita el motor de búsqueda de GitHub Pages
├── index.html             ← página de entrada: descripción del proyecto, equipo, vista previa
├── hierarchy.html         ← mapa de jerarquía de módulos y clases
├── modules.html           ← índice de todos los módulos documentados
├── media/
│   └── landingPage.png    ← captura de la landing page (0 bytes, placeholder)
├── assets/                ← CSS, JS e SVG para la UI de la documentación
│   ├── style.css
│   ├── highlight.css
│   ├── main.js
│   ├── hierarchy.js
│   ├── navigation.js
│   ├── search.js
│   ├── icons.js
│   ├── icons.svg
│   └── icons.png
├── classes/               ← documentación de clases (Cloudinary, etc.)
├── functions/             ← documentación de funciones por módulo
├── interfaces/            ← documentación de interfaces (DTOs, modelos)
├── modules/               ← documentación de módulos por archivo fuente
├── variables/             ← documentación de variables y constantes exportadas
└── graphs/                ← grafo de dependencias (generado por madge)
```

### Cómo regenerar

```bash
npm run build:docs
```

El comando regenera todo el contenido de `docs/` a partir de los comentarios
JSDoc del código fuente. Los archivos se versionan en git para que la
documentación sea accesible sin necesidad de ejecutar el comando.

## 2. `.gitignore` — limpieza de reglas TypeDoc

### Qué pasó

Se eliminaron las reglas de exclusión de TypeDoc del `.gitignore`:

**Antes:**
```gitignore
# TypeDoc autogenerated docs (regenerated each build, not versioned)
/docs/*
# Dependency graph (versioned — commit when architecture changes)
!/docs/graphs/
```

**Después:**
```gitignore
# (reglas eliminadas, docs/ queda sin exclusión)
```

### Por qué

Las reglas anteriores excluían todo `docs/` del tracking de git excepto
`docs/graphs/`. Esto era inconsistente: la carpeta se regeneraba en cada
build pero solo una sub-carpeta se versionaba. La solución fue versionar
todo el contenido de `docs/` como documentación estática del proyecto.

### Impacto

- `docs/` ahora está completamente trackeado por git.
- `dev.db-shm` y `dev.db-wal` **siguen sin estar** en `.gitignore` (ver
  sección 3).

## 3. Cambio pendiente: `dev.db-shm` y `dev.db-wal` en `.gitignore`

> Nota: este punto ya fue identificado como parcial en
> `cambios-no-registrados.md` §8 pero **aún no se ha resuelto**.

El `.gitignore` actual incluye `dev.db` pero **no** incluye los archivos de
memoria compartida y write-ahead log de SQLite:

- `dev.db-shm`
- `dev.db-wal`

Estos archivos se generan automáticamente al abrir una conexión SQLite con
WAL mode y pueden causar conflictos de merge o ruido en `git status`.

### Corrección propuesta

Agregar al `.gitignore`:

```gitignore
dev.db-shm
dev.db-wal
```

## 4. PR #53 — Eliminación de Cloudinary (abierta)

> Esta sección documenta un cambio **pendiente de merge** que afecta la
> arquitectura del proyecto.

La PR #53 propone eliminar `cloudinary` y toda la configuración asociada
del proyecto. Si se mergea, los siguientes archivos serán eliminados o
modificados:

| Archivo | Acción |
|---|---|
| `src/config/cloudinary.ts` | Eliminado |
| `src/services/product.service.ts` — `withImageFallback` | Eliminado o modificado |
| `src/controllers/pages/pages.controller.ts` — referencias a Cloudinary | Modificado |
| Dependencia `cloudinary` en `package.json` | Eliminada |

### Impacto en la documentación existente

- `cambios-no-registrados.md` §3 registra `cloudinary.ts` como parte del
  stack actual. Si se elimina, esa sección queda obsoleta.
- `ecommerce-spec-sprint1.md` §0 menciona Cloudinary como parte de la
  arquitectura. Debería actualizarse para reflejar su eliminación.
- `documentacion-typedoc.md` §1 lista `config/cloudinary` como módulo
  documentado. Debería actualizarse tras el merge.
